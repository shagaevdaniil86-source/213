# ПР14 Ответы на вопросы

## 1. В чем разница между Fetch API и XMLHttpRequest? Какие преимущества предоставляет Fetch API?

Fetch основан на Promise, интегрируется с async/await и поддерживает Request/Response и потоки. XMLHttpRequest использует события и имеет upload.onprogress, что удобно для прогресса отправки. В работе Blob отправляется через XHR именно для этого события.

## 2. Как обрабатываются ошибки в Fetch API и почему ответ с HTTP статусом 404 не вызывает reject промиса?

Fetch отклоняется при сетевой ошибке или отмене, но HTTP 404 — полученный ответ, поэтому Promise выполнен успешно. Нужно проверять response.ok/status. checkedFetch выбрасывает HttpError при статусе вне 200–299.

## 3. Какие методы HTTP поддерживает Fetch API и в каких случаях используется каждый из них?

GET получает данные, POST создаёт или запускает действие, PUT заменяет ресурс, PATCH меняет часть, DELETE удаляет, HEAD получает заголовки, OPTIONS сообщает возможности. Некоторые заголовки и методы ограничиваются CORS и режимом запроса.

## 4. Как работать с заголовками запроса и ответа в Fetch API? Приведите примеры полезных заголовков.

В options.headers задаются Content-Type, Authorization и учебный X-Custom-Header; response.headers.get() и перебор читают ответ. В браузере видны только разрешённые CORS заголовки. FormData не требует ручного Content-Type, чтобы сохранить корректный boundary.

## 5. В чем разница между PUT и PATCH запросами и когда следует использовать каждый метод?

PUT обычно отправляет полное представление ресурса, PATCH — набор частичных изменений. В работе PUT передаёт id/title/body/userId, PATCH — только title. Точное поведение определяется конкретным API.

## 6. Как реализовать авторизацию в Fetch API (Basic Auth, Bearer Token, OAuth2)?

Basic передаёт base64 от login:password, Bearer — токен. OAuth2 — протокол получения и использования токенов, а не отдельный метод fetch. Требуется HTTPS; секреты нельзя зашивать в клиентский код. Здесь используются только учебные значения, а неверный токен проверяется локально, поскольку JSONPlaceholder игнорирует авторизацию.

## 7. Какие способы отмены запросов существуют в Fetch API и когда их следует использовать?

Передать signal от AbortController и вызвать abort(), либо применить таймаут с очисткой таймера. Отмена нужна при смене экрана, устаревшем поиске и долгой загрузке. requestWithTimeout различает TimeoutError и ручной AbortError.

## 8. Как работать с разными форматами данных (JSON, FormData, Blob, ArrayBuffer) в Fetch API?

JSON: JSON.stringify + Content-Type, response.json(). FormData: объект формы без ручного boundary. Blob: response.blob() и object URL для изображения. ArrayBuffer: response.arrayBuffer() для двоичного разбора. Тело ответа обычно читается один раз; для повторного чтения нужна clone().

## 9. Как оптимизировать производительность при работе с множественными запросами (параллельное выполнение, кэширование)?

Promise.all ускоряет независимые запросы, последовательность нужна для зависимых ID. Кэш с TTL и объединение незавершённых Promise уменьшают сеть. В createFetchCache кэшируются только GET, ключ учитывает заголовки и credentials, данные копируются.

## 10. Какие лучшие практики существуют для работы с Fetch API в production приложениях?

Проверять status, обрабатывать сеть/таймаут/отмену, валидировать ответ, не публиковать секреты, очищать object URL и таймеры. Повторять только временные ошибки идемпотентных запросов с ограничением и backoff. Тестировать отказ, пустой ответ, неверный JSON и истечение TTL.
