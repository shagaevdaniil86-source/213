# ПР1 Ответы на вопросы

## 1. Какие три основные области работы с файлами в Git (рабочая папка, индекс, репозиторий) и чем они отличаются?

Рабочая папка содержит редактируемые файлы. Индекс хранит подготовленный снимок следующего коммита. Репозиторий (.git) хранит коммиты, объекты и ссылки веток. Изменение файла само по себе не меняет индекс или историю.

## 2. Что происходит при выполнении команд:

git add копирует текущее содержимое выбранных файлов в индекс. git commit записывает снимок индекса в локальную историю. git push отправляет объекты и обновляет ветку удалённого репозитория; незакоммиченные файлы он не отправляет.

## 3. Почему важно писать информативные сообщения к коммитам а не просто "исправление" или "update"?

Сообщение объясняет цель изменения и помогает найти нужный коммит или причину ошибки. Например, «ПР1: создан файл ответов» точнее, чем «update».

## 4. Чем отличается git add имя_файла от git add .? В каких случаях лучше использовать каждый вариант?

git add имя_файла подготавливает только указанный путь. git add . подготавливает изменения в текущем каталоге и его подкаталогах, включая удаления. Первый вариант удобен для точечного коммита, второй — когда все изменения относятся к одной задаче.

## 5. Что показывает команда git status и как меняется ее вывод на разных этапах работы?

git status показывает ветку, связь с upstream, неотслеживаемые файлы, подготовленные и неподготовленные изменения. После add файл перемещается в staged changes; после commit эти изменения исчезают, если рабочая папка совпадает с коммитом.

## 6. Для чего нужна команда git remote add origin URL и что означает слово "origin"?

Команда регистрирует удалённый адрес под именем origin. origin — принятое имя, а не специальное ключевое слово. Здесь адрес: https://github.com/shagaevdaniil86-source/213.git.

## 7. Зачем нужен флаг -u в команде git push -u origin main при первой отправке изменений?

-u устанавливает origin/main как upstream локальной main. После этого git push и git pull могут использовать эту связь без повторного указания удалённой ветки.

## 8. Что такое ветка (branch) по умолчанию и какая у вас создалась (main или master)? Почему это важно?

Ветка по умолчанию — основная ветка проекта, открываемая GitHub и используемая при клонировании. В этой работе явно создана main. Правильное имя важно для push, CI и ссылок на файлы.

## 9. Как просмотреть историю коммитов и какую информацию о каждом коммите вы видите?

git log показывает SHA, автора, дату и сообщение коммита. git log --oneline даёт краткий список, --stat — статистику файлов, -p — изменения строк. История этого репозитория содержит отдельные этапы ПР1 и практические работы.

## 10. Что произойдет, если сделать изменения в файле, но не выполнить git add перед git commit?

Обычный git commit записывает только индекс. Неподготовленные изменения останутся в рабочей папке; если индекс пуст, новый коммит не создаётся. git commit -a подготавливает изменения отслеживаемых файлов, но не новые файлы.
