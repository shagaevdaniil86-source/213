# ПР17 Ответы на вопросы

## 1. В чем разница между управляемыми и неуправляемыми компонентами в формах React?

Управляемое поле получает value или checked из React state, onChange обновляет state. У неуправляемого поля текущее значение хранит DOM: React задаёт defaultValue/defaultChecked, а чтение выполняется через ref или FormData. Обе формы регистрации управляемые, ContactFormUncontrolled читает значения через useRef.

## 2. Когда следует использовать управляемые компоненты, а когда - неуправляемые?

Управляемые поля удобны для проверки при вводе, зависимых полей, предварительного просмотра и синхронизации нескольких компонентов. Неуправляемые подходят для простых форм с чтением при submit, интеграции сторонних контролов и файлового ввода. Нельзя переключать один input между undefined и строковым value без намеренной смены режима.

## 3. Какие методы используются для обработки событий в формах React?

В JSX используются onChange для изменения полей, onSubmit для отправки формы, onReset для сброса, при необходимости onBlur для проверки после ухода фокуса. Обработчику передаётся объект события. В формах обработчики объявлены функциями и получают event, а кнопки имеют явный type.

## 4. Как обрабатывать несколько полей ввода с одним обработчиком?

Каждому полю задаётся name, совпадающий с ключом объекта состояния. Общий обработчик читает name, type, value и checked: для checkbox берётся checked, для остальных — value; setData(previous => ({...previous, [name]: nextValue})) сохраняет другие поля. Радиокнопки одного выбора имеют общий name и разные value.

## 5. Какие подходы к валидации форм в React вы знаете?

Можно использовать нативную Constraint Validation API и атрибуты required/minLength/type, собственную проверку объекта данных, библиотеки форм и схемы. В базовой форме действуют HTML-ограничения. Во второй форме noValidate отключает встроенные всплывающие сообщения, validateRegistration проверяет все поля и совпадение паролей; ошибки связаны через aria-describedby и aria-invalid. В реальном сервисе сервер повторно проверяет данные.

## 6. Как предотвратить стандартное поведение формы (перезагрузку страницы)?

В обработчике submit вызывается event.preventDefault(). Он отменяет стандартную навигацию, после чего React проверяет данные и показывает результат. Возврат false из обработчика React для этого не используется. В работе формы не выполняют сетевых запросов.

## 7. Что такое "поднятие состояния" (lifting state up) в контексте форм?

Общее состояние переносится в ближайшего общего родителя, если поля или компоненты должны использовать одно значение. Родитель передаёт значения и onChange детям через props. В работе формы хранят data, а RegistrationFields получает data и обработчик и рисует общий набор полей; он не создаёт второе независимое состояние.
