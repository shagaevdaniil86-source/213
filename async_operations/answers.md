# ПР13 Ответы на вопросы

## 1. В чем разница между Promise.then().catch() и async/await с try/catch? Когда следует использовать каждый подход?

.then/.catch удобны для цепочек преобразования, async/await — для последовательной логики, похожей на синхронную. Оба основаны на Promise. await выбрасывает причину rejection, которую обрабатывает try/catch.

## 2. Как работает Promise.all и что происходит, если один из промисов в массиве завершается ошибкой?

Promise.all ждёт все успешные результаты в порядке входного массива. При первом rejection результирующий Promise отклоняется; остальные операции автоматически не отменяются. Подходит, когда нужны все данные.

## 3. В чем разница между Promise.all, Promise.race и Promise.allSettled? Приведите практические примеры использования каждого.

all нужен для полного набора данных, race — для первого завершения (успеха или ошибки), allSettled — для статуса каждой операции. На странице показаны загрузка нескольких результатов, первый таймер и статистика смешанных исходов.

## 4. Как реализовать повторные попытки (retry logic) для асинхронных операций с экспоненциальной задержкой?

После временной ошибки повторить операцию с возрастающими задержками: base×2^attempt. Ограничить число повторов, учитывать отмену и идемпотентность. retryWithBackoff трактует maxRetries как повторы после первой попытки.

## 5. Что такое "состояние гонки" (race condition) в асинхронном коде и как его избежать?

Race condition возникает, когда порядок завершения меняет итог, например старый запрос поиска перезаписывает новый. Помогают AbortController, идентификаторы актуального запроса и проверка поколения. Интервал в работе проверяет поколение после await.

## 6. Как работает кэширование результатов асинхронных запросов и какие стратегии кэширования существуют?

Map хранит результат по ключу запроса; можно кэшировать Promise для объединения одновременных вызовов. Стратегии: постоянный кэш, TTL, LRU, обновление в фоне. Ошибки удаляются из кэша, возвращаемые данные копируются.

## 7. Какие методы оптимизации производительности можно применить при работе с множественными асинхронными операциями?

Независимые операции выполнять параллельно, зависимые — последовательно. Ограничивать конкурентность, объединять одинаковые запросы, кэшировать и отменять устаревшие. В работе Promise.all сравнивается с последовательной цепочкой.

## 8. Как обрабатывать ошибки в цепочках промисов и предотвращать "проглатывание" ошибок?

Возвращать Promise из then, использовать catch на нужном уровне и повторно выбрасывать неожиданные ошибки. Не оставлять fire-and-forget без обработчика. Здесь кнопки используют единый try/catch/finally и восстанавливают доступность после ошибки.

## 9. В чем преимущества использования async/await по сравнению с традиционными промисами и обратными вызовами?

async/await делает последовательные зависимости и try/finally читаемыми, уменьшает вложенность callback. Он не превращает операцию в синхронную и не отменяет необходимость явно запускать параллельные запросы.

## 10. Как отлаживать асинхронный код и какие инструменты разработчика наиболее полезны для этого?

Полезны async stack traces, breakpoints до и после await, Network для статусов и задержек, Console для rejected Promise. Автотесты используют подменённый fetch для повторяемой проверки HTTP ошибок, кэша и последовательности без зависимости от сети.
