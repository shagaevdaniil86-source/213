# ПР16 Ответы на вопросы

## 1. В чем разница между useState и useReducer? Когда использовать каждый?

useState удобен для независимых простых значений и небольших объектов. useReducer выносит связанные переходы в чистую функцию reducer(state, action). В корзине действия ADD_ITEM, REMOVE_ITEM, UPDATE_QUANTITY и CLEAR_CART обрабатываются централизованно; секундомер использует START, STOP, TICK, LAP, RESET. Reducer не изменяет прежнее состояние.

## 2. Как работает массив зависимостей в useEffect? Что произойдет если его не указать?

React сравнивает зависимости через Object.is. С [value] эффект запускается после первого commit и при изменении value; с [] — при монтировании. Без массива эффект выполняется после каждого commit. Очистка вызывается перед повторным эффектом и при размонтировании. Эффект, который без условия меняет state после каждого commit, способен создать цикл. StrictMode в разработке дополнительно проверяет установку и очистку.

## 3. Что такое "stale closure" в хуках и как использовать функциональные обновления чтобы избежать этой проблемы?

Stale closure — замыкание, читающее значения из прежнего рендера. Например, setInterval с setCount(count + 1) и пустыми зависимостями может постоянно использовать начальный count. setCount(previous => previous + 1) получает актуальное предыдущее состояние. Если эффект зависит от других реактивных данных, функциональное обновление не отменяет необходимость корректных зависимостей.

## 4. Когда действительно нужны useCallback и useMemo? Не являются ли они преждевременной оптимизацией?

useMemo кэширует результат вычисления, useCallback — идентичность функции до изменения зависимостей. Они полезны для измеренно дорогих вычислений или передачи стабильного callback в memo-компонент. В ExpensiveCalculation результат зависит только от number, а независимый счётчик его не меняет; кнопка memo получает useCallback. Без измеренной пользы мемоизация может усложнять код и быть преждевременной оптимизацией. Это оптимизация, а не гарантия корректности.

## 5. Как useRef отличается от useState? В каких сценариях useRef незаменим?

useState вызывает рендер при изменении значения. useRef сохраняет изменяемый объект с current между рендерами, но запись current сама по себе не перерисовывает UI. Ref нужен для фокуса DOM-элемента, хранения идентификатора ресурса и предыдущего значения. В FocusInput ref ссылается на input; в PreviousValue эффект запоминает значение после commit. Важное для отображения состояние обычно хранится в state.

## 6. Какие правила хуков существуют и почему их нельзя нарушать?

Hooks вызываются только на верхнем уровне React-компонентов или кастомных hooks. Нельзя вызывать их в циклах, условиях, обработчиках, вложенных функциях или после условного раннего возврата: React связывает вызовы с состоянием по стабильному порядку. Компоненты и hooks должны оставаться чистыми при рендере; побочные эффекты выполняются в обработчиках или эффектах.

## 7. Как создать кастомный хук и какие лучшие практики следует соблюдать?

Кастомный hook — функция с именем use…, объединяющая state и эффекты под удобным интерфейсом. В работе useLocalStorage возвращает значение и setter, useFetch — data/loading/error, useToggle — флаг и стабильное переключение, useDebounce — отложенное значение, useWindowSize — размеры. Нужно задавать полный список зависимостей, очищать ресурсы и обрабатывать ошибки. Каждый вызов имеет собственное состояние, если общий источник отдельно не организован.

## 8. В чем преимущества использования useContext перед передачей props через несколько компонентов?

Context позволяет читать общие данные из ближайшего Provider без передачи через все промежуточные компоненты. Это удобно для темы и локали. ThemeProvider хранит тему и передаёт мемоизированный объект, ThemeToggle читает его через useContext. Context не заменяет все локальные state и не исключает обновления потребителей при изменении value.

## 9. Как обрабатывать асинхронные операции в кастомных хуках?

Асинхронную функцию запускают внутри эффекта; сам callback эффекта не делают async, потому что он должен возвращать функцию очистки, а не Promise. useFetch проверяет response.ok, обрабатывает сеть и JSON, хранит loading/error/data. При смене URL и размонтировании AbortController отменяет запрос, а флаг active не позволяет устаревшему ответу перезаписать состояние.

## 10. Какие способы отладки хуков вы знаете?

Полезны React DevTools для props/state и Profiler, вкладка Network для запросов, breakpoints и логи эффектов, ESLint с правилами hooks, StrictMode для проверки очистки. В работе автоматические тесты проверяют изменения состояния, reducer, таймеры, debounce, отмену запросов и storage; браузерная кнопка отдельно проверяет наличие демонстраций.
