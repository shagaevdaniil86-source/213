# ПР15 Ответы на вопросы

## 1. В чем разница между функциональными и классовыми компонентами в React? Когда следует использовать каждый тип?

Функциональный компонент — функция, возвращающая JSX; состояние и эффекты задаются hooks. Классовый компонент наследует Component, использует render, this.props, this.state и методы жизненного цикла. Для нового кода обычно выбирают функции. Классы нужны при поддержке существующего кода и для изучения классового API. Здесь оба вида реализованы по заданию.

## 2. Что такое props и state? Как они отличаются и какие правила их использования?

Props — входные данные от родителя, их нельзя изменять внутри компонента. State — память компонента, обновляемая через setState или setter useState. Объекты и массивы копируются, а не изменяются на месте. Если новое значение зависит от старого, используется функциональное обновление: setCount(c => c + 1).

## 3. Как работает поднятие состояния (lifting state up) и в каких ситуациях это необходимо?

Общее состояние переносится в ближайшего общего родителя. Дети получают значения и обработчики через props. Это нужно для синхронизации нескольких контролов и устранения дублирующихся источников данных. В ThemeProvider хранится тема, общая для переключателя и всей страницы; Context доставляет её потомкам.

## 4. Какие методы жизненного цикла классовых компонентов вы знаете и для чего они используются?

componentDidMount выполняет действия после монтирования, componentDidUpdate — после обновления, componentWillUnmount очищает ресурсы перед удалением. В DataFetcher сравниваются прежний и новый URL перед загрузкой. Timer очищает интервал, WindowSizeTracker удаляет resize listener. Есть также shouldComponentUpdate для оптимизации и componentDidCatch для границ ошибок.

## 5. Как работают хуки useState и useEffect? Какие правила использования хуков существуют?

useState возвращает состояние и setter. useEffect синхронизирует компонент с внешними системами после commit; возвращённая функция очищает эффект. Без массива зависимостей эффект выполняется после каждого commit, с [] — при монтировании, с [value] — при изменении value. Hooks вызываются на верхнем уровне компонента или кастомного хука, в одинаковом порядке, не внутри условий или циклов. Все используемые реактивные значения включаются в зависимости. StrictMode в разработке дополнительно проверяет установку и очистку эффектов.

## 6. Что такое ключи (keys) в React и почему они важны при рендеринге списков?

Key идентифицирует элемент среди соседей между рендерами и помогает React сопоставлять состояние и DOM. Ключ должен быть стабильным и уникальным в своём списке. TodoList использует собственный id задачи, поэтому одинаковые тексты не конфликтуют. Индекс опасен при вставках, удалениях и перестановках. Key не передаётся как обычный prop.

## 7. Как обрабатывать события в React и чем это отличается от нативного JavaScript?

Обработчики передаются в JSX: onClick={handler}, onChange={handler}. Имена пишутся в camelCase, передаётся функция, а не строка кода. React предоставляет объект события с preventDefault и stopPropagation. В классе используются стрелочные методы для сохранения this. Слушатели внешних объектов, например window.resize, всё равно требуют addEventListener и очистки.

## 8. Что такое управляемые и неуправляемые компоненты? В чем их разница?

Управляемое поле получает value или checked из React state, а onChange обновляет состояние — React является источником истины. Неуправляемое поле хранит значение в DOM; начальное значение задаётся defaultValue, чтение возможно через ref или FormData. LoginForm, TodoList, SearchBox и UserProfile используют управляемые поля. Нельзя незаметно переключать поле между undefined и строковым value.

## 9. Как работает контекст (Context) в React и когда его следует использовать?

createContext создаёт канал для общих данных. Provider задаёт value, useContext читает ближайший Provider. При изменении value потребители обновляются. Context подходит для темы, локали и общих настроек, избавляя от передачи props через промежуточные уровни. Он не заменяет все локальные state. Здесь ThemeProvider хранит выбор, ThemeToggle изменяет его.

## 10. Какие преимущества предоставляют кастомные хуки и как создавать собственные хуки?

Кастомный hook — функция с именем use…, которая вызывает другие hooks и возвращает удобный интерфейс. Он переиспользует логику состояния и эффектов, но не автоматически объединяет состояние разных вызовов. useFetch возвращает data/error/loading и отменяет запрос при смене URL. useLocalStorage возвращает значение и setter, обрабатывает неверный JSON, недоступную запись и события другой вкладки.
